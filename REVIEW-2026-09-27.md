## 2. Before merging: build and smoke test

1. Full build as usual (`bun run scripts/dev.ts tauri build --no-bundle
   --features cuda`), then `bun cargo test -p koharu-app --features cuda`
   and `bun cargo test -p koharu-rpc -p koharu-runtime`. koharu-app,
   koharu-rpc and the Tauri crate were **not compiled as crates here**
   (section 7). `Cargo.lock` already drops `tauri-plugin-updater`; the build
   shouldn't need to change it.
2. File access (`bc69467`): Export → Rendered to the default folder and to
   another folder, a single-file PSD and KHR export, Import folder, Open
   .khr. A "forbidden path" error means the narrowed scope missed a flow:
   restore the `**` line in `crates/koharu/capabilities/default.json` and
   tell me which action failed.
3. Speed (`5b9d837`, `8728071`): on a disposable project copy with Flux2,
   time "Process all" on ~16 pages with and without
   `KOHARU_PIPELINE_CHUNK=1`. Look for `running pages in chunks` and
   `unloaded engines to free GPU memory` in `--debug` logs; there should be
   one unload per chunk instead of one per page.
4. Failure skipping (`bdfbd8d`): with a wrong OpenRouter key, Process a page.
   It should still be inpainted, and only the render skipped.
5. Repair brush during a batch (`8728071`): the stroke now waits for the
   current GPU step (up to one Flux2 page) instead of running beside it.

## 4. Spec: features, security and QoL before the UI overhaul

Ordered by value for the translate-and-touch-up workflow. Each item notes
what the new UI will need, so the overhaul can be designed around it. None
requires a scene-format change unless marked; every API change needs the
usual `generate:api` in the same commit.

**S1. Job queue with project ownership** (M). Builds on the GPU gate.
Jobs get `status: queued | running | …`, `project_id`, `pages`,
`created_at`; `GET /operations` is sorted and pruned (O11). Closing or
switching projects cancels that project's jobs, or asks (O2). The UI shows a
queue instead of a spinner, and queued jobs can be cancelled.

**S2. Protect hand edits** (S, then M). Step 1: a `translateMissingOnly`
pipeline option, default on for batch runs, that skips blocks which already
have a translation (O3). Step 2 (optional, **scene v9** with a frozen v8
decoder): a per-block `locked` flag honoured by translate and render
defaults. The UI's "Translate" button would offer "missing only" /
"retranslate all".

**S3. Project glossary and page context for OpenRouter** (M). A
`glossary.toml` inside the `.khrproj` (it travels in `.khr` exports and needs
no scene bump) with names, honorifics and terms, plus the previous page's
source→translation pairs, injected into the structured-translation prompt.
`GET/PUT /projects/current/glossary`. The best lever on consistency across a
chapter; it needs a blind A/B like your OCR work.

**S4. Automatic project snapshots** (M). On close and every Nth compaction,
keep the last ~10 `scene.bin` copies in `.khrproj/snapshots/`. Blobs are
immutable, so each snapshot is just the small scene file. Add "Restore
snapshot" (itself undoable). This protects against bad batch runs and
migration bugs, with no format change.

**S5. Storage report and cleanup** (M). Nothing ever deletes old renders,
inpaints or masks, so projects and `.khr` exports only grow. Show the size
and reclaimable bytes per project; "Clean up" deletes blobs referenced by
neither the scene nor any snapshot (S4), only when the project is closed or
freshly opened (undo stacks are in memory, so that is safe). Robust
reference collection: every 64-hex string in the JSON-serialized scenes, so
future fields can't be missed.

**S6. Safer delete** (S). Move to `projects/.trash/` (or the Recycle Bin)
with "Empty trash"; never half-delete (O6).

**S7. Reopen the last project on startup** (S). From the AGENTS backlog: the
backend remembers the last project id in config and opens it once the
runtime is ready; the UI simply finds a project open.

**S8. Export quality of life** (S-M). Source page names (O10), Unicode
project names, server-side export to a dialog-chosen folder (no in-memory
zip, no IPC copy, O18), parallel PNG encoding, and compaction only for `.khr`
(O17).

**S9. One instance, working `.khr` files** (S-M). See O5.

**S10. Retry what failed** (S-M). The driver now knows, per page, which
steps failed or were skipped (`MissingArtifacts`). Return that in the job
result and add "Retry failed steps", which reruns exactly those units: after
an OpenRouter outage, one click re-translates and renders the affected
pages.

**S11. Overlap translation with GPU work** (M, unmeasured). While Flux2
inpaints chunk *k*, translate chunk *k+1*: translation is remote and never
takes a GPU turn, and today the GPU idles during every translation step.

**S12. Webview hardening** (S each). `on_navigation` lock; CSP header
(start with `Content-Security-Policy-Report-Only`: `default-src 'self';
script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
img-src 'self' blob: data:; font-src 'self' blob: data:; connect-src 'self';
object-src 'none'; base-uri 'none'; frame-ancestors 'none'`, then enforce
once the console is clean); the remote capability narrowed to the actual
port; a token for non-loopback binds (O9); MCP off by default (O19).

**S13. Startup that explains itself** (S). O4's dialog, and the same for a
failed runtime download (the Retry screen exists, but only once the window
is up).

**S14. Memory** (M, unmeasured). O7's byte-budgeted cache; share decoded
source images between steps of the same page.

**S15. Testability** (M). `App::new` initializes the llama.cpp backend
eagerly (`crates/koharu-app/src/app.rs:95`), so neither `App` nor
`llm::Model` can be built in tests without the runtime libraries. Make it
lazy (first local-LLM use), then move the harness's end-to-end pipeline test
into `koharu-app` and add route tests for import, export and repair brush.
